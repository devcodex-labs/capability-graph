# 添加本地知识

<span className="cg-status">接入片段；本地读取有可运行示例</span>

当能力需要长说明时，把正文放入 Knowledge，短用途仍写在 Capability 摘要。本页延续[进阶 G1](./progressive-discovery#g1-child-capability)的 route.http；最小 G0 尚无子能力，不能直接读取它。完整文件和可运行脚本见[独立 G2 步骤](./progressive-discovery#g2-local-knowledge)，本页解释字段和失败边界。

## 1. 放置文档

将 Markdown 或文本放在 Provider 权威根内，例如 `knowledge/routing.md`，内容使用 G2 给出的完整文档。

## 2. 关联能力

以下是**配置片段**，合并进已有能力文件，保留其必填名称、描述、使用时机和已有关系；不要用片段覆盖整个文件。

```json
{
  "capabilityId": "route.http",
  "knowledge": [{
    "kind": "document",
    "knowledgeId": "routing-guide",
    "role": "guide",
    "locale": "en",
    "locator": {
      "type": "relative-file",
      "path": "knowledge/routing.md"
    }
  }]
}
```

## 3. 只读取已选能力

查询片段：在当前 discover.mjs 内复制 G2 的 open/forProvider/try/finally，用下面代码替换 try 内查询。provider 是当前程序绑定 acme.http 的对象，修订从当前目录取得，不跨进程复用变量：

```ts
const catalog = await provider.listCatalog();
const requiredStaticRevision = catalog.meta.staticRevision;
const result = await provider.readDocuments({
  selected: ['route.http'],
  knowledgeIds: ['routing-guide'], roles: ['guide'], locales: ['en'],
  requiredStaticRevision
});
for (const item of result.results) {
  if (item.ok) console.log(item.value.knowledgeId, item.value.text);
  else console.error(item.error.code, item.error.nextAction);
}
```

Core 会校验相对路径仍位于 Provider 根的真实路径中，并按条目返回内容或错误。符号链接不能绕过根边界。`role` 用于按用途过滤，`locale` 用于精确语言匹配，不做自动语言回退。

`knowledgeId` 用于在已选能力的知识集合中继续收窄；`locator.path` 相对 Authority 根，不相对脚本位置。`kind: document` 允许精确读取；没有知识需求时不必配置该数组。

## 预期结果

成功项的 `value.knowledgeId` 为 `routing-guide`，`value.text` 与 knowledge/routing.md 一致，`contentId` 标识实际字节。空 selected 无效；拼错知识 ID、文件缺失或越界应检查逐项错误，不能解释成“没有知识”。只改正文无需重建能力身份；改关联需重新加载静态定义。接口 Promise 成功不代表每项 ok。

下一步需要全文检索时再考虑[检索 Adapter](../integrations/capability-retriever)，不要把 Collection 当作可直接拼接的文档。

## 当前边界

- Collection 不能整读；可以先列成员再按成员 ID 精确读取，全文检索需要 `KnowledgeRetriever`。
- HTTP/HTTPS 引用需要 `KnowledgeReader`；没有 Reader 会返回明确未配置错误。
- 知识只从非空已选能力集合展开；需要依赖闭包时先调用 `resolveSelection()`，仅 `requires` 被展开。
