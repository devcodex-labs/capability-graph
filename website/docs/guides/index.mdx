# 使用指南

先完成最小 Provider，再按当前目标选择任务。不必为一次目录发现同时配置知识、检索、Runtime 和 MCP。

| 任务 | 需要先准备 | 路径与预期结果 |
|---|---|---|
| 按需增加能力/知识/上下文/规范 | 最小 Provider G0 | [渐进发现与按需读取](./progressive-discovery)：独立可执行的 G1–G4 检查点 |
| 确定 Provider 和能力粒度 | 作者能描述产品职责 | [建模 Provider](./model-a-provider)：稳定身份与可选择的能力边界 |
| 表达层级、特化或必要上下文 | 已有能力定义 | [设计关系](./design-relations)：选对关系及方向；只有 requires 进入 Selection |
| 按选择读本地文档 | 已有能力与知识文件 | [添加本地知识](./add-local-knowledge)：完整路由声明及可核对的正文身份 |
| 观察项目真实实例 | 实现 RuntimeAdapter；并非 npm 自带后端 | [使用运行时](./use-runtime)：项目/环境过滤、观察和兼容证据 |
| 联合发现多个文件来源 | 每个 Provider 一个 Authority | [使用多个 Provider](./multiple-providers)：独立修订、二元身份及按操作区分的失败边界 |
| 修改定义并安全刷新 | 当前 graph 由程序自己管理 | [管理生命周期与重新加载](./lifecycle-and-reload)：可执行的新修订、previous 与失败恢复 |
| 消费截断或部分结果 | 已取得结果/错误与 meta | [处理错误与部分结果](./errors-and-partial-results)：续页、逐项处理或查询级恢复 |

完整可执行路径会给出运行命令与预期输出；依赖注入/替换片段只描述合并位置，不代表已经交付真实后端。
