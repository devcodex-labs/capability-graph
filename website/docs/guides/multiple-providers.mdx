# 使用多个 Provider

<span className="cg-status">可用</span>

在 `open()` 时声明宿主允许、集成启用和每个 Provider 的唯一 Authority：

前置为最小 G0 的 providers/acme-http 两个定义。另建 providers/acme-database，保存以下两个完整 JSON。acme.database 只是示例身份，仍用文件 Authority，不代表提供真实数据库后端。

```json title="providers/acme-database/provider.json"
{
  "providerId": "acme.database",
  "name": "Acme Database",
  "version": "0.1.0"
}
```

```json title="providers/acme-database/capabilities/query.json"
{
  "capabilityId": "query",
  "name": "Database query",
  "description": "Describe how to query application data.",
  "whenToUse": "The task needs a database query capability."
}
```

以下 TypeScript 代码放在安装项目根；两个 rootDir 都相对当前脚本。使用 JavaScript 时原样保存为 .mjs 也可运行：

```ts
import { fileURLToPath } from 'node:url';
import { CapabilityGraph } from '@devcodex/capability-graph';

const graph = await CapabilityGraph.open({
  hostAllowedProviders: ['acme.http', 'acme.database'],
  integrationEnabledProviders: ['acme.http', 'acme.database'],
  providers: [
    { providerId: 'acme.http', authority: { kind: 'file', definitionLayout: 'directory',
      rootDir: fileURLToPath(new URL('./providers/acme-http/', import.meta.url)) } },
    { providerId: 'acme.database', authority: { kind: 'file', definitionLayout: 'directory',
      rootDir: fileURLToPath(new URL('./providers/acme-database/', import.meta.url)) } }
  ]
});
try {
  const page = await graph.listCatalog({
    requestProviderScope: ['acme.http', 'acme.database'], limit: 40
  });
  const http = graph.forProvider('acme.http');
  const detail = await http.getCapabilities(['route']);
  console.log({ ids: page.items.map(({ qualifiedId }) => qualifiedId),
    meta: page.meta, nextCursor: page.nextCursor, detail });
} finally {
  await graph.close();
}
```

预期 ids 恰为 acme.database::query、acme.http::route，meta.scope 含两者，staticRevisionByProvider 分别记录来源修订。检查完整性/游标与 detail.results[0].ok；多个 Provider 不共用单个 requiredStaticRevision，选择一个后用绑定查询取得真实修订。

联合目录保留二元身份，不创建跨 Provider 图边，不把相同 capabilityId 合并。接入方负责租户认证，requestProviderScope 只能收窄有效范围。

## 选择之后

以下是上面 try 内查询的替换片段，不能在 finally 已关闭之后继续执行；G0 查询 route，不假定 route.http 已定义：

```ts
const selectedProvider = graph.forProvider('acme.http');
const selectedDetail = await selectedProvider.getCapabilities(['route']);
```

## 来源更新或读取失败时如何处理

文件定义在 open/reload 时校验后载入内存。当前目录查询不重新扫描磁盘；某个 Provider 的刷新失败时，旧 current 继续可读，联合 `listCatalog` / `listProviders` 仍可返回结果，并用 `refreshFailed` 标记失败。首次加载失败则拒绝 open。

| 场景 | 结果 | 调用方处理 |
|---|---|---|
| 定义更新无效或定义文件丢失，reload 失败 | 保留已校验的 current，其他 Provider 可独立刷新成功 | 检查 reload 的逐 Provider 错误，修复定义后再次刷新 |
| 文档被删除或 Reader 读取失败 | readDocuments/readSpecification 保留成功项及失败槽位；Catalog 不因正文失败失效 | 按 locator/knowledgeId 修复来源，不能把失败项当空文档 |
| 批量详情混入未知或越界身份 | 正常槽位继续成功，失败项携带原错误 | 检查每项 ok，按原输入槽位处理详情 |
| graph 已关闭或指定修订已退休 | 查询级失败，包括联合 listCatalog | 重建实例或重新发现，不能静默替换要求的修订 |

可复现的失败刷新及逐项隔离见[多 Provider 隔离测试](../examples/multi-provider)。跨 Provider 组合由 Agent 或上层工作流完成，不写入静态关系。

## VextJS 与 MonSQLize 的真实来源

推荐分别创建 providers/vextjs/provider.json、providers/vextjs/capabilities/*.json，以及 providers/monsqlize/ 下相同结构。每个 Provider 可选 knowledge/，无需复制所有指南。provider 或 providers 只是容器名称；Core 分别显式注册每个根，不自动发现多个 Provider。

在各 providers[] 配置 knowledgeRoots：directory 绑定获准官方文档目录；package 使用 packageName 和消费项目 resolveFrom 固定实际安装包根。locator 的 root 引用别名；HTTP URL 则通过已配置 Reader 读取。定义根与文档根用途不同，业务项目状态由宿主维护。

真实验证入口为根 scripts/validation/provider-sources.mjs，覆盖原始官方长/短文、外部目录、实际安装包 README 和可选固定 HTTPS。vextjs.mjs 另核验原生 MCP 回读。两 Provider 可有相同本地 capabilityId/knowledgeId，结果仍按 providerId 隔离；不建立跨 Provider requires。固定 Vext 安装包未包含 website，不能假定完整指南在 node_modules 内。
