# 结果与控制元数据

<span className="cg-status">可用</span>

| 字段 | 语义 |
|---|---|
| `completeness` | `complete`、`truncated` 或 `partial` |
| `compositeStaticRevision` | 本次实际 Provider 修订集合的组合身份 |
| `staticRevision` | 单 Provider 查询的修订 |
| `staticRevisionByProvider` | 多 Provider 查询的修订映射 |
| `servedFrom` | `current`、`previous` 或 `mixed`；多 Provider 查询可混合修订来源 |
| `servedFromByProvider` | 多 Provider 查询中每个 Provider 对应 `current` 或 `previous` |
| `refreshFailed` | 最近刷新失败，但当前返回视图仍可读 |
| `scope` | 本次有效 Provider 范围 |
| `filter` | 实际应用的查询过滤 |
| `view` | 本次使用的能力、Runtime 和知识内容身份 |
| `warnings` | 有界非致命诊断 |
| `budgets` | 实际相关的预算值 |

`CurrentCapabilityView` 是查询证据，不是需持久化的合并实体，也不承诺跨来源事务。

## 批量结果

```ts
type BatchItem<T> =
  | { inputIndex: number; ok: true; value: T }
  | { inputIndex: number; ok: false; error: ErrorShape };

interface BatchResult<T> {
  results: readonly BatchItem<T>[];
  meta: ResultMeta;
}
```

失败项保留在结果数组中，但 `inputIndex` 的含义取决于操作：

| 操作 | `inputIndex` 的含义 | 如何关联结果 |
|---|---|---|
| `getCapabilities()` | 原始 `ids` 数组的索引；重复身份也保留各自槽位 | 用 `ids[item.inputIndex]` 对齐请求 |
| `readDocuments()` | 能力选择展开、过滤和去重后生成的读取/错误槽位索引 | 成功项用 `value.id` 与 `value.knowledgeId` 关联；失败项检查 `error` 及其可选诊断 |
| `readSpecification()` | 规范文档过滤后生成的读取/错误槽位索引 | 成功项用 `value.providerId` 与 `value.knowledgeId` 关联；失败项检查 `error` 及其可选诊断 |

文档读取的结果数可以与 `selected` 或 `knowledgeIds` 的长度不同。`knowledgeIds` 是筛选条件，不规定返回顺序；读取结果的 `inputIndex` 不能作为这两个请求数组的索引。

例如 Provider 已声明 `SPEC-01`，但没有 `missing`，调用绑定对象的 `provider.readSpecification({ knowledgeIds: ['missing', 'SPEC-01'] })`，结果可以投影为：

```json title="specification-slots.json"
[
  { "inputIndex": 0, "ok": true, "knowledgeId": "SPEC-01" },
  { "inputIndex": 1, "ok": false, "code": "CG_NOT_FOUND", "knowledgeId": "missing" }
]
```

这里成功文档来自 `value.knowledgeId`，未知 ID 来自该错误的 `error.details.knowledgeId`；`inputIndex: 0` 对应的不是请求第一项 `missing`。其他失败不保证携带同样的诊断字段。

页级 `meta.completeness` 描述整个操作，逐项错误描述特定槽位；指定修订不可读等全局承诺失败会直接抛出查询级错误。

## Provider 作用域

Open 阶段的 Effective Provider Scope 是 `hostAllowedProviders ∩ integrationEnabledProviders`，查询提供 `requestProviderScope` 时再求一次交集。请求范围只能收窄；包含未允许 Provider 时返回 `CG_SCOPE_DENIED`。`BoundProviderGraph` 固定单 Provider并拒绝 `requestProviderScope`；ID 前缀、parent 和类型过滤都不是授权。

## 静态与运行时修订

Static Revision 来自规范化 Provider metadata、能力记录、关系和知识映射，知识正文使用独立 contentId。Core 每个 Provider 保留 current 和 previous；`requiredStaticRevision` 匹配 previous 时 `servedFrom` 为 `previous`，更旧或不可读修订返回 `CG_REVISION_MISMATCH`。

Runtime Revision 由 Adapter 定义，观察同时记录 `observedAgainstStaticRevision`。兼容状态只有 `compatible`、`unknown` 和 `refresh_required`；Core 不因 ID 相同自动判断兼容。

## 分页与游标

条目分页游标按各接口绑定原请求范围、过滤、有效 limit 和修订，续页保留相应条件。正文 `readDocumentPage/readSpecificationPage` 的游标绑定文档、来源、静态修订及全文内容身份；允许在有效预算内更改下一页 `maxBytes`，但不能同时传 `cursor` 和 `startOffset`。最终公开游标编码后最多 32,768 个 base64url 字符；输入超限为 `CG_INPUT_INVALID`，输出超限为 `CG_BUDGET_EXCEEDED`。

邻居八个关系组各自分页。续页只提交仍有 `nextCursor` 的 `kinds` 和对应 `cursors`。页大小和总字节预算同时生效，提高响应字节预算不会放宽游标长度上限。

## 预算与完整性

| 操作 | 关键默认预算 |
|---|---|
| Catalog | 24,576 页字节、200 项、2,048 单项字节 |
| Neighbors | 50 默认页、100 最大页、24,576 页字节、2,048 单项字节 |
| Detail | 20 能力、16,384 单项字节、131,072 总字节 |
| Selection | 32 个显式能力、128 个闭包能力、256 条依赖边 |
| Document read | 默认页 32,768 字节、全文每次 8 文档；大文档可续读 |
| Specification documents | 每页 20 项、131,072 页字节；正文仍受 Document read 预算约束 |
| Capability retrieval | 20 候选、512 单候选字节 |
| Knowledge query | 32 个原始 selected、每维 128 个过滤值、128 个最终 targets、8 命中、2,048 单个 snippet 字节 |
| Runtime | 50 默认页、100 最大页、5,000 ms 等待、4,096 facts 字节 |

字节预算使用 UTF-8 或原始 bytes，不是 JavaScript 字符数。条目查询的 `truncated` 表示有续页，`partial` 表示检查 warning 或逐项失败。正文页的 `partial` 表示本页未包含整个文档，即使读取成功且没有 warning/error；续读看 `hasMore/nextCursor`。仅从偏移 0 返回完整正文时，completeness 为 `complete`。单项过大不会被截断成看似合法的数据；无法取得进展时返回 `CG_BUDGET_EXCEEDED`。

Selection 按选择、节点和依赖边数量限制工作量，当前没有独立的响应总字节预算。可通过 `OpenConfig.budgets.selection` 覆盖 `maxSelected/maxNodes/maxEdges`；原始选择在去重前计数。

## 预算字段与默认值

以下是 `BudgetConfig` 的全部字段，均为 number。`BudgetOverrides` 仅允许一层分组内省略字段；省略项保留默认值，不整组替换。覆盖值必须为正的有限整数，不能为 null/undefined 或未知字段；默认页不能超过有效最大页，错误为 CG_CONFIG_INCOMPLETE。查询 limit 与配置覆盖不同：查询的正安全整数超过有效上限时会收敛到上限。

| 字段 | 默认值 | 单位/含义 |
|---|---|---|
| `catalog.maxBytes` | 24576 | UTF-8 页字节 |
| `catalog.maxItems` | 200 | 项/页，也为缺省 limit |
| `catalog.maxItemBytes` | 2048 | UTF-8 单项字节 |
| `neighbors.defaultPageSize` | 50 | 每种关系缺省数量，也为详情关系摘要缺省数量 |
| `neighbors.maxPageSize` | 100 | 每种关系上限 |
| `neighbors.maxBytes` | 24576 | 关系页共享 UTF-8 字节 |
| `neighbors.maxItemBytes` | 2048 | UTF-8 单邻居字节 |
| `detail.maxCapabilities` | 20 | 原始详情请求能力数量 |
| `detail.maxItemBytes` | 16384 | UTF-8 单详情字节 |
| `detail.maxBytes` | 131072 | UTF-8 整次详情字节 |
| `detail.defaultKnowledgePageSize` | 20 | 顶层知识/Collection 成员缺省数量 |
| `detail.maxKnowledgePageSize` | 100 | 知识摘要/成员数量上限 |
| `specification.defaultPageSize` | 20 | 规范文档路由缺省数量 |
| `specification.maxPageSize` | 100 | 规范文档路由数量上限 |
| `specification.maxBytes` | 131072 | UTF-8 规范路由页字节 |
| `specification.maxItemBytes` | 16384 | UTF-8 单规范路由字节 |
| `selection.maxSelected` | 32 | 去重前显式选择数量 |
| `selection.maxNodes` | 128 | 完整闭包节点数量 |
| `selection.maxEdges` | 256 | 完整闭包真实依赖边数量 |
| `read.maxBytes` | 32768 | 旧全文接口的单篇返回字节预算，超限逐项失败 |
| `read.maxPageBytes` | 32768 | 独立分页/流式块字节预算，不限制文档总大小 |
| `read.maxDocumentsPerCall` | 8 | 整次正文读取文档数量 |
| `read.maxSelected` | 32 | 文档读取原始 selected 数量，去重前检查 |
| `read.maxFilterValuesPerDimension` | 128 | 直接读取每维 knowledgeIds/roles/locales 原始数量 |
| `read.maxResponseBytes` | 4194304 | 完整 Core 响应的 JSON UTF-8 字节，含失败槽位、meta 和 view |
| `retrieveCapabilities.maxCandidates` | 20 | 候选数量，也是缺省 limit |
| `retrieveCapabilities.maxCandidateBytes` | 512 | UTF-8 单候选字节 |
| `queryKnowledge.maxHits` | 8 | 命中数量，也是缺省 limit |
| `queryKnowledge.maxSnippetBytes` | 2048 | UTF-8 单片段字节 |
| `queryKnowledge.maxSelected` | 32 | 原始 selected 数量 |
| `queryKnowledge.maxFilterValuesPerDimension` | 128 | 每维过滤原始值数量 |
| `queryKnowledge.maxTargets` | 128 | 最终文档目标数量 |
| `queryKnowledge.maxTargetBytes` | 131072 | 最终目标集合 UTF-8 字节 |
| `runtime.defaultPageSize` | 50 | 实例缺省页数量 |
| `runtime.maxPageSize` | 100 | 实例页数量上限 |
| `runtime.timeoutMs` | 5000 | Core 最长等待毫秒，不是取消 |
| `runtime.maxFactsBytes` | 4096 | 每实例 facts UTF-8 字节 |
| `runtime.maxAssociationBytes` | 2048 | 每实例整个 associations 的 UTF-8 字节 |

例如 `budgets: { runtime: { timeoutMs: 2000 } }` 只更改等待时间，所有其他默认值保留。增加预算需要结合宿主资源，不使 scope 变成沙箱或后端自动可用。

新增的三个 read 数量/响应字段在公开配置中可省略，内部总会补齐默认值，旧完整 BudgetConfig 仍可使用。原始数量在查询 pin、点读及 Reader 前检查；展开后的篇数超限也不调用 Reader。总响应需取得有界正文后按 JSON 转义后的字节计算，超限为查询级 CG_BUDGET_EXCEEDED，不能静默丢项。单篇正文超限仍是逐项失败。宿主可降低响应上限以适应自己的上下文容量。
