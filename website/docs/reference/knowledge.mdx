# 知识接口

<span className="cg-status">可用</span> <span className="cg-status">仅合同</span>

## KnowledgeRef

KnowledgeRef 是 Document 或 Collection；两者都必须显式填写 `kind` 和 `knowledgeId`。知识 ID 与角色的 ASCII 格式见[ID 格式与值约束](./provider-definition#id-格式与值约束)。可选字段可以省略，提供时不能是 `null`，字符串不能为空白；未知字段会被拒绝。

### Document 字段

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `kind` | 字符串常量 | 是 | 固定为 `document` |
| `knowledgeId` | 字符串 | 是 | 1–128 个 ASCII 字符，符合知识 ID 格式 |
| `locator` | 对象 | 是 | 必须符合下方两种 locator 之一 |
| `role` | 字符串 | 是 | 与知识 ID 相同格式；例如 `guide` 或 `reference`；规范文档固定为 `specification` |
| `locale` | 字符串 | 否 | 最多 128 UTF-8 字节；用固定 IANA 注册表校验并规范化 BCP 47 标签，例如 `en`、`zh-CN` |
| `title` | 字符串 | 否 | 最多 256 UTF-8 字节 |
| `summary` | 字符串 | 否 | 最多 2,048 UTF-8 字节 |
| `canonicalUrl` | 字符串 | 否 | 最多 2,048 UTF-8 字节；HTTP/HTTPS URL，且必须已是 `new URL(value).href` 的规范形式 |

`locale` 过滤按规范化后的标签精确匹配，没有父语言回退。长度按字节计算，例如 86 个中文汉字通常已超过 title 的 256 字节上限。`canonicalUrl` 是展示元数据，不替代实际读取来源；如 `https://example.com/` 合法，省略末尾 `/` 的 `https://example.com` 不符合其规范形式要求。

### Collection 字段

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `kind` | 字符串常量 | 是 | 固定为 `collection` |
| `knowledgeId` | 字符串 | 是 | 1–128 个 ASCII 字符，符合知识 ID 格式 |
| `members` | Document 数组 | 是 | 每项包含上表完整的必填字段；允许 `[]`，集合内成员 ID 不能重复 |
| `title` | 字符串 | 否 | 最多 256 UTF-8 字节 |
| `summary` | 字符串 | 否 | 最多 2,048 UTF-8 字节 |

Collection 没有聚合正文，也没有自己的 locator、role、locale 或 canonicalUrl。同一 Provider 中重复使用一个知识 ID 时，必须保持完整映射一致，包括成员及可选元数据；具体冲突规则见[定义与身份](./provider-definition#capability-定义)。

### Locator 字段

| `type` | 其他必填字段 | 约束 |
|---|---|---|
| `relative-file` | 字符串 `path` | 缺省相对 Authority 知识根；可选 `root` 指向该 Provider 的知识根别名。支持中文、空格、`@scope`，以 `/` 分隔；拒绝绝对路径、空段、`.`/`..`、反斜杠、冒号、控制字符、段尾点/空格与真实路径越界 |
| `http` | 字符串 `url` | 可解析的 HTTP/HTTPS URL；需要匹配的自定义 Reader 才能读取 |

Document 最小映射示例，可合并到能力定义的 `knowledge` 数组：

```json title="document-ref.json"
{
  "kind": "document",
  "knowledgeId": "routing-guide",
  "role": "guide",
  "locator": { "type": "relative-file", "path": "knowledge/routing.md" }
}
```

这里的 `path` 相对 Provider 知识根，不相对脚本或终端目录。文件来源的知识根即 Authority 根；数据库来源使用该只读视图的 `knowledgeRootDir`。缺失正文可通过定义加载，实际读取时返回失败；已经存在但越界的符号链接会在加载阶段被拒绝。完整创建文件和读取正文的步骤见[进阶 G2](../guides/progressive-discovery#g2-local-knowledge)。

1.1.0 支持在 `providers[]` 每项配置 `knowledgeRoots.docs = { kind: 'directory', rootDir: '/approved/docs' }` 或 `knowledgeRoots.installed = { kind: 'package', packageName: '@scope/library', resolveFrom: '/consumer/project' }`。locator 例如 `{ type: 'relative-file', root: 'installed', path: 'README.md' }`，公开 source 为 `root:installed/README.md`。根、包版本和 manifest 指纹在私有 view 中捕获；不执行包入口，不发给 Retriever。安装包未包含的文档需另绑定官方目录或 URL。

## readDocuments

`ReadDocumentsQuery` 包含非空 `selected`、可选 `knowledgeIds/roles/locales`、范围和修订。同维取并、异维取交；先筛选再应用每次最多 8 篇的预算和 Reader。`DocumentReadBatch` 的 `knowledgeState` 区分无关联、筛选后为空和匹配，逐项结果保留错误槽。`DocumentRead` 携带能力身份、文档路由元数据、来源、内容类型、内容身份、正文和精确字节。

只有在 `knowledgeIds` 明确写出成员 ID 时才直接读取 Collection 成员；仅给 Collection ID 不会整读。远程 Document 需要 `KnowledgeReader`。

读取会展开所选能力的知识、过滤并去重，一个能力可以产生多个文档槽位。成功项用 `value.id` 与 `value.knowledgeId` 关联；`inputIndex` 是生成后的槽位索引，不对应原始 `selected` 或 `knowledgeIds` 数组。详见[批量结果](./result-meta#批量结果)。

| 调用或选项 | 合同与默认行为 |
|---|---|
| `graph.readDocuments({ selected })` | 每项是 `CapabilityRef`；`selected` 必须非空 |
| `graph.forProvider(id).readDocuments({ selected })` | 每项是该 Provider 的本地 ID 字符串，不能再传 `requestProviderScope` |
| 省略 `knowledgeIds` | 读取匹配的直接 Document；Collection 成员必须显式选择 |
| 省略 `roles/locales` | 不限制对应维度；locale 规范化后精确匹配，无父语言回退 |
| `knowledgeIds/roles/locales: []` | 合法但匹配为空；不要与 `queryKnowledge` 不允许空 `knowledgeIds` 的规则混淆 |
| 正文预算 | 每次最多 8 篇；全文读取受单次完整响应预算保护，文档总大小不设准入门槛；大文档使用下方分页接口 |
| 原始输入预算 | selected 默认最多 32 项；knowledgeIds/roles/locales 每维默认最多 128 项，重复值也计数，超限在点读前失败 |
| 完整响应预算 | 默认 4 MiB JSON UTF-8 字节，包含正文转义、失败槽位和元数据；超限为查询级 `CG_BUDGET_EXCEEDED`，需要拆批或过滤 |
| 单篇失败 | 缺失文件、无匹配 Reader、非法 UTF-8、Reader 合同错误或全文超过单次响应容量产生失败槽位；改用分页可继续读取大文档 |

具体 Reader 选择、来源身份和错误码见[Reader 与 Adapter](./runtime-adapter#knowledgereader)。这里的默认值可以通过 `budgets.read` 调整，不能绕过所选修订和 Provider 范围。

## readSpecification

`ReadSpecificationQuery` 限定一个 Provider，可按 `knowledgeIds/locales` 筛选；正文仅在该方法被显式调用时读取。`SpecificationReadBatch` 保留逐篇成功或错误，成功项 `SpecificationDocumentRead` 以 `providerId` 标识来源，不伪造 Capability ID。无规范、筛空和匹配可区分；单次仍受 8 篇预算。

成功项用 `value.providerId` 与 `value.knowledgeId` 关联；筛选 ID 不规定返回顺序，`inputIndex` 不对应原始 `knowledgeIds` 数组。未知 ID 可以在已匹配的文档槽位之后返回错误。

顶层 `graph.readSpecification({ providerId, ... })` 必须传 `providerId`；绑定后的 `graph.forProvider(id).readSpecification()` 可省略整个参数，并且不能另传 `providerId`。省略 `knowledgeIds/locales` 表示不限制对应维度，空数组表示筛空。默认正文与篇数预算同 `readDocuments`，单篇读取失败仍保留其他结果；但来源视图不可读、修订不匹配或篇数超限会使本次查询失败，而不是返回部分正文。

## queryKnowledge

`KnowledgeSearchTarget` 只含最终过滤后的公开文档映射，不含绝对知识根或 `readContext`。原始数组、最终目标数与目标 JSON 字节数均有预算，超限时 Retriever 不会被调用。后端的 `KnowledgeHit` 使用 UTF-8 字节偏移，`endOffset` 为开区间；Core 核验后生成带正式路由元数据的 `KnowledgeResultHit`。`KnowledgeIndexEvidence` 必须证明映射、配置和内容身份与当前请求一致，即使零命中也不能省略。

每个最终文档都需实际来源核验。外部索引不调用 access.read/scan 时，Core 通过 Reader 独立核验正文哈希与命中范围；相同的自报哈希不是来源证明。正确零命中也需可读来源，缺 Reader 或来源失败不能返回 current。

## 正文分段读取

<span className="cg-status">可用</span>

`DocumentBodyQuery` 与 `SpecificationBodyQuery` 分别用于 `readDocumentPage()`、`readSpecificationPage()`。选择能力和文档后，模型决定读取范围与是否继续。小文档一页可包含全文；大文档使用 `nextCursor` 连续读完，无需改写来源或提高整篇门槛。

```ts
const provider = graph.forProvider('seed.http');
let cursor: string | undefined;
do {
  const page = await provider.readDocumentPage({
    capabilityId: 'route.validation', knowledgeId: 'D-02',
    ...(cursor ? { cursor } : {}),
  });
  // 根据 page.text 决定是否继续；此处示意读取全部页。
  cursor = page.nextCursor;
} while (cursor);
```

`DocumentBodyPage` 明确返回 UTF-8 字节范围 `startOffset/endOffset`、总字节数 `totalBytes`、本页 `byteLength`、`hasMore` 与可选 `nextCursor`。`complete` 只在本次返回整篇时为 true；末页不等于全文。全文 `contentId` 和 `pageContentId` 分别计算，保留 BOM 与原始换行。默认页大小 32768 字节，由 `read.maxBytes` 控制，单次 JSON 响应仍受 `read.maxResponseBytes` 保护。

可指定 `startOffset/maxBytes` 读取范围，或传 `cursor` 续读；不能同时指定 `cursor/startOffset`。偏移必须在 UTF-8 边界。分页优先在较近的段落或围栏行结束；超长单行、代码块通过明确的连续范围读取。游标绑定 Provider、文档身份、静态修订、来源路径和全文哈希。来源正文变化，即使静态修订没变，旧游标也返回 `CG_REVISION_MISMATCH`。

本地读取逐块计算完整哈希并检查打开文件的身份与变更；HTTP 参考 Reader 支持无 Range 的来源，流式读取全文，只保留所选范围，整体期限或 `signal` 会终止实际连接。每页核验全文意味着额外 I/O，不能把范围响应字节数当实际来源读取量。旧 Reader 仅实现 `read` 时采用有界全文回退；超过回退容量或需要真实取消时应实现 `stream`。失败后已启动的读取与资源清理完成才结束查询。

HTTP 源码参考支持注入宿主 Agent 兼容代理，在仓库外保存受容量、条目及期限约束的完整快照。强 ETag 的 304 可复用已取得正文；无验证器、弱 ETag 或超缓存预算回退流式全文 GET。ETag 不替代内容哈希，200 新正文拒绝旧 cursor，未经完整来源证明的 206 被拒绝。全文、Specification、分页和检索保留原始 BOM/CRLF；MD/MDX 的 MIME 一致。
