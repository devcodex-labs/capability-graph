# Core 与生命周期

<span className="cg-status">可用</span>

`CapabilityGraph` 是协议无关的顶层入口。它拥有 Authority 视图生命周期，但不启动 API 或 MCP 服务。

| 方法 | 作用 | 关键约束 |
|---|---|---|
| `CapabilityGraph.open(config)` | 校验配置和全部初始 Authority | 任一初始来源失败则拒绝 open |
| `forProvider(providerId)` | 创建 Provider 绑定查询 facade | 共享图生命周期，不绑定修订 |
| `listProviders(query?)` | 列出范围内 Provider | 不读取 Specification 正文 |
| `getProvider(providerId, query?)` | 读取 Provider metadata 和来源状态 | 返回 `meta`、`servedFrom`、`refreshFailed` |
| `listCatalog(query?)` | 跨 Provider 平坦发现 | 有界、可分页、保留二元身份 |
| `getCapabilities(ids, query?)` | 批量读取能力详情 | 保留输入槽位和逐项失败 |
| `getNeighbors(ref, query?)` | 分页读取六种关系组 | 单 Provider、非递归 |
| `readDocuments(query)` | 读取已选能力的 Document | 选择非空，Collection 不支持直接读 |
| `retrieveCapabilities(query)` | 可选候选召回 | 不替代目录，需配置 Retriever |
| `queryKnowledge(query)` | 检索已选知识 | 返回证据片段，不生成答案 |
| `queryRuntime(query)` | 查询运行实例 | 需要 Provider、项目和环境 |
| `reload(options?)` | 串行刷新一个或全部 Provider | 每个 Provider 独立发布结果 |
| `close()` | 停止新工作并释放 Core 资源 | 不取消 Adapter 自有任务 |

方法的准确类型由包内 `dist/index.d.ts` 提供；本页的公共符号覆盖由生成器校验。

## BoundProviderGraph

通过 `graph.forProvider(providerId)` 获得。绑定对象把查询限制在一个 Provider，并允许使用 Provider 内 `capabilityId` 字符串。

| 方法 | 与顶层方法的差异 |
|---|---|
| `getProvider()` | 不再传 providerId |
| `listCatalog()` | `parent` 可省略 providerId |
| `getCapabilities(ids)` | `ids` 是 Provider 内字符串数组 |
| `getNeighbors(capabilityId)` | 只接受 Provider 内字符串 ID |
| `readDocuments({ selected })` | `selected` 是字符串数组 |
| `retrieveCapabilities()` | 召回限制在绑定 Provider |
| `queryKnowledge()` | 缺省 Provider 身份由绑定补全 |
| `queryRuntime()` | Runtime 来源固定为绑定 Provider |

绑定查询禁止传 `requestProviderScope`，即使 JavaScript 调用方绕过 TypeScript 也会得到 `CG_INPUT_INVALID`。Facade 不拥有 Authority 句柄，也没有独立 `close()`；生命周期仍由原 `CapabilityGraph` 管理。

## OpenConfig 与 Authority

```ts
interface OpenConfig {
  hostAllowedProviders: readonly string[];
  integrationEnabledProviders: readonly string[];
  providers: readonly ProviderLoadSpec[];
  budgets?: BudgetOverrides;
  runtimeAdapters?: readonly RuntimeAdapter[];
  readers?: readonly KnowledgeReader[];
  knowledgeRetriever?: KnowledgeRetriever;
  capabilityRetriever?: CapabilityRetriever;
}

type AuthoritySpec =
  | { kind: 'file'; rootDir: string }
  | { kind: 'database'; adapter: DatabaseAuthorityAdapter };
```

每个有效启用 Provider 必须恰有一个 Authority。文件根在 `open()` 时解析并固定；数据库 read view 在交给 Core 后成为稳定逻辑快照。

`reload({ providerId? })` 返回每个 Provider 的 `servedFrom`、修订、刷新状态和可选错误。一个刷新失败不回滚其他 Provider 已成功发布的新视图，也不删除仍可读取的旧 current。
