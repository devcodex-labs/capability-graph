# Adapter 接口

<span className="cg-status">Core 接口：<strong>可用</strong>；后端按下文接入</span>

## RuntimeAdapter

一个 Provider 最多配置一个 Runtime Adapter。`query()` 输入项目、环境、可选实例过滤、当前静态修订、limit 和 cursor；输出实例、观察和可选续页游标。

Core 验证：

- Provider、项目和环境匹配请求；
- `instanceOf` 是当前 Provider 的已有静态能力；
- facts、association 和游标满足预算；
- observation 的修订、兼容、availability 和 freshness 合法；
- `requiredRuntimeRevision` 不被静默切换。

Adapter 自己管理连接、取消、重试和清理。Core 的 5 秒默认超时只停止等待，并处理返回给 Core 的 `query()` Promise 的迟到拒绝。Adapter 另行启动的后台任务仍须自行处理拒绝与资源释放；不能把超时视为底层任务已经取消。

Adapter 抛出的 CapabilityGraphError 中，CG_REVISION_MISMATCH 保留 nextAction=refresh；CG_RUNTIME_RESULT_MISMATCH / CG_RUNTIME_CONTEXT_REQUIRED 保留 fix_input。私有 message/details 被剥离；未知异常和期限到期仍为 CG_RUNTIME_UNAVAILABLE。

## CapabilityRetriever

<span className="cg-status">合同与可运行参考</span>

输入查询文本、允许的 Provider IDs、每个 Provider 的当前 Static Revision 和候选上限；输出候选身份、可选 score 与 `sourceStaticRevision`。

Core 按 Adapter 原始顺序生成一基 `rank`。候选被拒绝时保留排名间隙，合法项不重排。Core 拒绝范围外 Provider、不存在的能力、不可读来源修订、超预算候选和其他违反合同的返回。

未指定修订时，一个来源不可读不应清空其他 Provider 的合法候选；指定修订不可读时查询级失败。

## KnowledgeRetriever

<span className="cg-status">合同与可运行参考</span>

`retrieve(input, access)` 只处理 Core 展开的最终 targets。每个 target 含能力身份、`knowledgeId`、声明 locator 和经过的 Collection IDs，不含绝对知识根或 `readContext`。

命中必须提供能力身份、`knowledgeId`、`contentId`、source、UTF-8 `startOffset`/`endOffset`、snippet 和可选 score。索引证据必须精确覆盖最终 targets Provider，证明每个文档的 source/indexed contentId、mapping/config revision、观察时间和 freshness；零命中也必须返回证据，Core 成功投影后给出明确 `knowledgeState`。

Core 限制 hits 数量、snippet 字节、内容边界和访问范围。过期证据不会降级为成功空结果。

## KnowledgeReader

<span className="cg-status">本地读取与 HTTP 参考可用</span>

`canRead(ref)` 同步决定是否支持非本地来源。Core 选择第一个匹配的自定义 Reader；内置本地 Reader 优先处理 `relative-file`。

可选 `isContentCurrent(ref, context, contentId, { signal? })` 用于正文续页的稳定来源核验。只有强验证器或不可变来源证明才能返回 true；false 重新完整扫描，故障必须抛错，不能用文件时间代替内容证明。Core 的私有副本每实例最多 4 MiB、16 条，超额仍可流式读取；详见[KnowledgeReader 接入](../integrations/knowledge-reader)。

`read(ref, context, { maxBytes })` 返回精确 bytes、contentType、contentId 和 source。Reader 不得替换声明 locator，必须遵守最大字节并保证 `contentId` 对应真实 bytes；`sourceContext.knowledgeRootDir` 不能进入公共响应。无匹配 Reader 使用 `CG_READER_UNCONFIGURED`，执行失败使用 `CG_READER_UNAVAILABLE` 或 Core 投影的读取错误。

context 的 sourceContext 仅供本地进程 Reader 使用，其结构包含必填 `providerId: string`、`authorityKind: 'file' | 'database'`、`sourceRevision: string`，以及可选 `knowledgeRootDir: string`（此 view 固定的私有绝对根）。它不是额外的公共导出，不应序列化到 Retriever 请求、模型上下文或文档查询结果。

## DatabaseAuthorityAdapter

<span className="cg-status">仅合同</span>

`openView(providerId)` 返回稳定 `DatabaseReadView`，暴露 Provider metadata、sourceRevision、可选知识根，以及 `getCapability()`、`scanCapabilities()`、`neighbors()` 和 `close()`。

同一 view 的 Provider、知识根、sourceRevision 和记录必须稳定。扫描记录按 capabilityId 严格升序且恰好一次；之后点读必须重现同一记录。Core 先完整扫描和收集 ID，再进行端点检查和 `parents`/`specializes`/`requires` 三类无环检查，不能边扫边判不存在。随后核对全部八类正反关系流。公开 Catalog 校验有序身份连续性及终止位置；关系查询核验完整来源流，再按 Core 位置分页。缺头、缺中、缺尾与假空流不能返回 complete。保留 O(V) 身份/摘要，不缓存全量数据库定义。Static Revision 使用与文件模式相同的规范序列化算法。

Core 拥有 `close()` 调用并在验证失败或视图退休时执行；仍有查询 pin 时延迟关闭。Adapter 不提供通用写入、CRUD 或迁移能力。

## 调用默认值、预算和失败方式

| 合同/调用 | 输入与输出边界 | 默认限制与失败方式 |
|---|---|---|
| retrieveCapabilities | 非空 text，允许 scope 与当前静态修订 → 候选身份/score/sourceStaticRevision，再投影 CapabilityCandidate | limit 默认/最大 20，单候选 512 字节；未配置 CG_RETRIEVER_UNCONFIGURED，后端异常 CG_RETRIEVER_UNAVAILABLE；不合法候选剔除并 warning/partial |
| queryKnowledge | 非空 text、非空 selected，knowledgeIds/roles/locales 可选 → QueryKnowledgePage | limit 默认/最大 8，snippet 2,048 UTF-8 字节；原始 selected 32、每维过滤 128、最终 targets 128/131,072 字节，检索前校验 |
| KnowledgeReader.read | 必填 Document、只在 Reader 内可用的 context、maxBytes → bytes/contentType/contentId/source | 返回完整有界字节；全文调用默认受 4 MiB 响应容量保护；contentId 为原始完整 bytes 的 SHA-256 前 16 位，source 精确等于 locator |
| KnowledgeReader.stream | 可选 Document/context/chunkBytes/signal → AsyncIterable 字节块 | 单块不超过 chunkBytes，总文档大小不设门槛；Core 计算完整哈希；取消和迭代器退出必须关闭实际 I/O |
| RuntimeAdapter.query | 必填 project/environment/currentStaticRevision/limit，可选 instanceOf/instanceId/cursor → RuntimeAdapterResult | 输入 limit 来自 runtime 有效预算；Core 默认等 5,000ms，不发送 AbortSignal；完整校验见[Runtime](./runtime) |
| DatabaseReadView 扫描/邻居 | StorePageRequest 必填 limit/maxBytes，cursor 可选 → StorePage&lt;T&gt; | 按收到的数量/字节预算返回严格有序且有进展的页；坏页/漂移使验证或查询失败，不以空页绕过合同 |

查询输入的所有字段/输出形状与 Adapter 方法参数在下方展开。limit 必须是正的安全整数，超过有效最大值时收敛到最大值；检索没有默认目录替代。queryKnowledge 的 selected 仍为 CapabilityRef 对象数组（包括绑定对象调用），不能照搬 readDocuments 的绑定字符串数组。

Reader 的精确表达式是 `contentId = 'k:' + createHash('sha256').update(bytes).digest('hex').slice(0, 16)`。对正文原始字节计算，不先解码、规范化换行或截取正文；完整 64 位哈希也会被 Core 判为内容身份不匹配。最小实现见 [KnowledgeReader 接入](../integrations/knowledge-reader#http-reader-骨架)。

queryKnowledge 只在最终选定文档内检索。有最终 targets 时，Retriever 返回零命中也需有效 evidence，knowledgeState 为 searched；展开后的空集合或过滤为空由 Core 返回 empty_collection/filtered_empty，不调用 Retriever。无关联知识为 CG_KNOWLEDGE_NOT_ASSOCIATED，不是成功空检索。KnowledgeHit 的偏移是 UTF-8 字节、end-exclusive，score 可选且须有限数值。命中附加 role/locale 等由 Core 从映射补全，不信任后端随意改写。

## 知识检索失败层级

| 场景 | 对外结果 | 层级与处理 |
|---|---|---|
| Static Revision 证据不匹配 | `CG_REVISION_MISMATCH` | 查询级失败；refresh，重新发现并核对最终 targets 的修订 |
| 索引证据无效或过期 | `CG_INDEX_STALE` | 查询级失败；refresh，重建受影响映射/配置/内容索引；包括缺失或非法 documents、非 current freshness |
| 原始检索页违反合同 | `CG_ADAPTER_CONTRACT_INVALID` | 查询级失败；例如 hits 不是数组或数量超过本次 limit，修复 Adapter 返回页 |
| 单项命中违反合同 | warning 中的 `CG_ADAPTER_CONTRACT_INVALID` | 剔除坏项，保留合法命中；meta.completeness 为 partial。身份范围或预算违规可使用对应 warning 码 |
| 有效证据、零命中 | `searched` | 成功，items 为空且有 indexStatus；不要将证据失败转换为此状态 |

evidence 的 staticRevisionByProvider 必须精确覆盖最终 targets；mapping/config/content revision 对齐，freshness 必须 current 才能成功。KnowledgeRetrievalAccess 只能读本次列出的身份/knowledgeId 对；`read` 受单次容量保护，新增可选 `scan` 以有界块消费全文并返回 `KnowledgeScanResult`，不限制文档总大小。retrieve 结束后保存的 access 不可再发起读取。小正文保留有界查询快照；大正文的命中再按范围复核，来源漂移产生 warning/partial，不能拼接新旧版本。

所有 id 为非空实现标识，不代表授权。可选 invalidate(change) 使用 SourceChange 的明确 reason 枚举；V1 Core **不自动调度 invalidate**。Runtime/Reader/Retriever 自己拥有连接、重试、取消与清理，只有数据库 view.close 的调用归 Core。实现步骤与骨架见[集成](../integrations/index)。
