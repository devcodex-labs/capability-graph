# 示例

按目标选择入口：首次发现使用[最小 Provider](../getting-started/first-provider)，按需增强使用[进阶教程](../guides/progressive-discovery)；下列 Seed 展示完整组合，需要源码仓库，不包含在 npm 安装结果中。

| 状态 | 含义与限制 |
|---|---|
| 可运行 | 有完整执行入口和自动验证路径，仍需按页准备依赖与文件；不等于生产认证/部署已实现 |
| 仅合同 | 类型/接口骨架及合同测试可核对，仍需实现实际后端 |

| 想验证什么 | 前置与状态 | 入口及证明范围 |
|---|---|---|
| 一个完整 Provider 的不同接入层 | 克隆源码并安装依赖；可运行 | [Seed 端到端示例](./seed-provider)：API、11 个查询工具 MCP 与 HTTP 文档读取 |
| HTTP 正文分页读取 | 根 npm run demo:http；可运行 | [HTTP 文档读取](./seed-provider#http-文档读取)：中文原文、来源变化、超时、取消和清理 |
| 多来源遇到故障是否保留合法项 | 根 npm test；可运行隔离测试 | [多 Provider 隔离测试](./multi-provider)：两个真实文件来源及失败刷新；批量点读与联合目录的边界不同 |
| 如何映射到 VextJS | 有前置条件的可运行源码示例；固定来源有独立 CI 实测 | [VextJS 集成](./vextjs-integration)：官方文档主题 Provider、原生 MCP 独立审计与全新安装消费者的来源读取验证 |

如果只是想试第一次查询，不需要先下载全部 Seed；按上面的最小 Provider 路径即可。
