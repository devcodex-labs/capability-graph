# 示例

按目标选择入口：首次发现使用[最小 Provider](../getting-started/first-provider)，按需增强使用[进阶教程](../guides/progressive-discovery)；下列 Seed 展示完整组合，需要源码仓库，不包含在 npm 安装结果中。

| 状态 | 含义与限制 |
|---|---|
| 可运行 | 有完整执行入口和自动验证路径，仍需按页准备依赖与文件；不等于生产认证/部署已实现 |
| 仅合同 | 类型/接口骨架及合同测试可核对，仍需实现实际后端；数据库 Adapter 当前属于此类 |
| 概念示例 | 只说明组合与职责，没有可运行实现，不宣称 VextJS Adapter 已交付 |

| 想验证什么 | 前置与状态 | 入口及证明范围 |
|---|---|---|
| 一个完整 Provider 的不同接入层 | 克隆源码并安装依赖；可运行 | [Seed 端到端示例](./seed-provider)：API、十二工具 MCP 与真实 HTTP Runtime，非通用后端 |
| HTTP 正文读取与词项检索 | 根 npm run demo:http；可运行 | [HTTP 文档与文本检索](./seed-provider#http-文档与文本检索)：中文正文、零命中、过期拒绝、显式重建及真实业务请求 |
| 多来源遇到故障是否保留合法项 | 根 npm test；可运行隔离测试 | [多 Provider 隔离测试](./multi-provider)：文件源加数据库假实现；批量点读与联合目录的边界不同 |
| 如何映射到 VextJS | 理解模型即可；概念示例 | [VextJS 集成](./vextjs-integration)：职责和采集设计，不含可导入 Adapter 或运行命令 |

如果只是想试第一次查询，不需要先下载全部 Seed；按上面的最小 Provider 路径即可。
