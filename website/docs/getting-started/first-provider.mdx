# 创建第一个 Provider

<span className="cg-status">可运行</span>

## 最快跑通

完成[安装](./installation)后，在当前项目创建本页三个文件，运行 `node discover.mjs`。不需要克隆仓库、TypeScript 编译器、知识文档、Specification、HTTP 服务或 MCP。

本页的成功目标只有一个：从真实文件定义发现 `acme.http` 的 `route` 能力。发现能力不等于执行路由业务。

## 前置条件与目标

使用安装页创建的 `capability-graph-demo/` 作为工作目录：

```text
capability-graph-demo/
├── package.json
├── discover.mjs
└── providers/acme-http/
    ├── provider.json
    └── capabilities/
        └── route.json
```

`package.json` 来自 npm 初始化和安装；其余文件按下面内容创建。所有命令在项目根执行，脚本以自身位置定位 Provider，不受终端后续切换目录影响。

## 1. 定义 Provider

```json title="provider.json"
{
  "providerId": "acme.http",
  "name": "Acme HTTP",
  "version": "0.1.0"
}
```

保存到 `providers/acme-http/provider.json`。

| 字段 | 必填 | 如何填写 |
|---|---|---|
| `providerId` | 是 | Provider 的稳定机器身份；必须与加载配置中的 `acme.http` 一致 |
| `name` | 是 | 展示名称；改名不改变机器身份 |
| `version` | 是 | Provider 定义版本，不是 npm 包版本，也不能代替查询的 Static Revision |

Specification 是可选的全局使用规则，本次无需填写空对象或空文档列表。需要时按[进阶教程的独立 G4 步骤](../guides/progressive-discovery#g4-provider-specification)接入。

## 2. 定义主能力

```json title="capabilities/route.json"
{
  "capabilityId": "route",
  "name": "Routing",
  "description": "Define how requests reach application handlers.",
  "whenToUse": "Choose a routing capability before changing an entrypoint.",
  "distinction": "A static capability family, not registered runtime routes."
}
```

保存到 `providers/acme-http/capabilities/route.json`。

| 字段 | 必填 | 如何填写 |
|---|---|---|
| `capabilityId` | 是 | Provider 内的稳定身份，本例为 `route` |
| `name` | 是 | 可读名称 |
| `description` | 是 | 这是什么能力，解决什么问题 |
| `whenToUse` | 是 | 哪些任务应该考虑它，不写成自动执行指令 |
| `distinction` | 否 | 说明它与容易混淆的能力或 Runtime 实例有什么不同 |

完成本教程需要 `provider.json` 和一个 `capabilities/*.json`。文件 Authority 也允许legacy 模式只含 `provider.json` 的空 Provider，此时 Catalog 返回完整空目录。Core 收集定义并完整校验，不从能力 ID 中的点号猜关系。本例没有关系和 Knowledge，均可直接省略。

增加子能力、关系和本地知识，见[渐进发现与按需读取](../guides/progressive-discovery)。Core 按精确目录名跳过 `.git`、`node_modules`、`dist`、`dist-test`、`coverage`、`.cache`、`.tmp`；正式定义不要放进这些目录。

## 3. 打开 Provider

下面完整脚本中的配置含义如下：

| 配置项 | 本例中的作用 |
|---|---|
| `hostAllowedProviders` | 宿主允许访问的 Provider 上限 |
| `integrationEnabledProviders` | 当前集成启用的 Provider，与宿主允许集合取交集 |
| `providers` | 为每个有效启用 Provider 配置唯一 Authority，不是允许名单 |
| `providers[].providerId` | 对应 `provider.json` 的身份 |
| `authority.kind` | `file` 表示读取文件定义，不导入业务源码 |
| `authority.rootDir` | 包含两个定义文件的真实根目录，本例相对 `discover.mjs` 定位 |

有效范围为 `hostAllowedProviders ∩ integrationEnabledProviders ∩ requestProviderScope`，未提供请求范围时使用前两者交集。有效启用的 Provider 缺少来源时返回 `CG_CONFIG_INCOMPLETE`，不是合法空目录。

## 4. 执行渐进查询

在项目根创建完整的 `discover.mjs`：

```js title="discover.mjs"
import { fileURLToPath } from 'node:url';
import { CapabilityGraph } from '@devcodex/capability-graph';

const graph = await CapabilityGraph.open({
  hostAllowedProviders: ['acme.http'],
  integrationEnabledProviders: ['acme.http'],
  providers: [{
    providerId: 'acme.http',
    authority: {
      kind: 'file', definitionLayout: 'directory',
      rootDir: fileURLToPath(new URL('./providers/acme-http/', import.meta.url))
    }
  }]
});

try {
  const provider = graph.forProvider('acme.http');
  const catalog = await provider.listCatalog({ limit: 20 });
  console.log(JSON.stringify({
    catalog: catalog.items.map(({ id }) => id.capabilityId),
    completeness: catalog.meta.completeness,
    hasNextCursor: Boolean(catalog.nextCursor)
  }, null, 2));
} finally {
  await graph.close();
}
```

```sh
node discover.mjs
```

1. `open()` 加载有效范围中的文件定义并校验，失败时不会生成可用图。
2. `forProvider('acme.http')` 把后续查询绑定到一个 Provider，可使用其内部能力 ID。
3. `listCatalog()` 返回平坦摘要，不读 Knowledge，不查询 Runtime，也不是“仅主能力”专用接口。
4. 输出把结果投影成能力 ID、完整性和是否还有下一页，便于核对。
5. `finally` 在成功或查询失败后关闭当前程序创建的 graph，释放权威视图句柄。

这里只定义了 `route`，因此 Catalog 恰好只有它；增加子能力后平坦目录也会列出子能力。首轮只展示主能力的入口策略归 Provider API/MCP，见[主能力接入](./provider-owned-api)。

## 预期结果与排错

```json
{
  "catalog": ["route"],
  "completeness": "complete",
  "hasNextCursor": false
}
```

三项同时符合，说明首次加载和目录发现成功；不是业务执行、知识读取或 Runtime 接入成功。`meta.completeness` 为 `partial` 或存在 `nextCursor` 时只是部分结果，不能当成全集；完整结果仍应留意 `meta.warnings`。

| 失败现象 | 优先检查 |
|---|---|
| 找不到 npm 包 | 是否在运行脚本所属项目安装 `@devcodex/capability-graph` |
| `CG_CONFIG_INCOMPLETE` | 有效启用的 Provider 是否有唯一来源配置 |
| `CG_LOAD_FAILED` | 文件目录、读权限和 JSON 是否能加载 |
| `CG_VALIDATION_FAILED` | 必填字段、Provider ID 与关系端点是否有效 |
| Catalog 没有 `route` | 两个 JSON 是否保存到配置的 Provider 根内，是否启用 `definitionLayout: 'directory'`，定义是否在 `capabilities/` 中 |
| 输出 `partial` 或有下一页 | 保留过滤条件与修订续查，不把这一页当全集 |

后续详情与文档返回批量 `results`，要逐项检查 `ok`，不能仅凭 Promise 成功就认定每项都成功。更多症状见[故障排查](../troubleshooting/index)。
