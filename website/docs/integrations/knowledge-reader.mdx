# KnowledgeReader 接入

<span className="cg-status">合同与可运行 HTTP 参考</span>

仓库提供[真实 Node.js HTTP Reader 参考](../examples/seed-provider#http-文档与文本检索)，验证来源限制、总时限、响应字节与连接清理；它属于源码示例，未作为主包导出。

内置本地 Reader 优先处理 `relative-file` Document。自定义 `KnowledgeReader` 只用于其他来源：

下面为接口节选。Reader 按已有引用精确读取全文；Retriever 则根据查询在已选知识中返回片段。要读取一篇远程指南只需 Reader，不必引入索引或模型。

```ts
interface KnowledgeReader {
  readonly id: string;
  canRead(ref: KnowledgeRef): boolean;
  read(
    ref: KnowledgeDocumentRef,
    context: KnowledgeReadContext,
    budget: { maxBytes: number }
  ): Promise<{
    bytes: Uint8Array;
    contentType: string;
    contentId: string;
    source: string;
  }>;
  stream?(ref: KnowledgeDocumentRef, context: KnowledgeReadContext,
    options: { chunkBytes: number; signal?: AbortSignal }):
    AsyncIterable<{ bytes: Uint8Array; contentType: string; source: string }>;
  isContentCurrent?(ref: KnowledgeDocumentRef, context: KnowledgeReadContext,
    contentId: string, options: { signal?: AbortSignal }): Promise<boolean>;
}
```

`canRead()` 必须同步、稳定。Reader 返回的 `source` 要与声明 locator 一致，并严格遵守字节预算；网络连接和资源释放归 Reader 所有。

`isContentCurrent` 是可选的正文续页优化合同，只能在强验证器或不可变来源身份证明当前正文仍匹配已完整核验的 `contentId` 时返回 `true`；不能只比较时间或自报哈希。`false` 让 Core 重新完整扫描，来源故障、取消或超时必须抛错。Core 每个实例最多保留 4 MiB、16 条私有正文副本，关闭时释放；超缓存容量的文档继续流式完整核验。旧 Reader 无需实现此方法。

`KnowledgeReadContext.sourceContext` 只用于本地读取，不能序列化进 Retriever 请求或公开响应。远程引用存在但无 Reader 时返回 `CG_READER_UNCONFIGURED`。

## HTTP Reader 骨架

下面的类型可编译，但 `readBounded` 是接入方必须提供的传输实现，不代表主包已有 HTTP 后端。它应在接收数据时累计字节、超限立即终止，并负责访问策略、认证、重定向和超时；不能先下载任意大小的正文再检查长度。

```ts title="reader-skeleton.ts"
import { createHash } from 'node:crypto';
import type { KnowledgeReader, KnowledgeDocumentRef, KnowledgeReadContext } from '@devcodex/capability-graph';

export function createHttpReader(
  readBounded: (url: string, maxBytes: number) => Promise<Uint8Array>,
  streamBounded?: (url: string, options: { chunkBytes: number; signal?: AbortSignal }) => AsyncIterable<Uint8Array>
): KnowledgeReader {
  return {
    id: 'acme-http-reader',
    canRead(ref) {
      return ref.kind === 'document' && ref.locator.type === 'http';
    },
    ...(streamBounded ? { async *stream(ref: KnowledgeDocumentRef, _context: KnowledgeReadContext, options: { chunkBytes: number; signal?: AbortSignal }) {
      if (ref.locator.type !== 'http') throw new Error('Unsupported locator');
      for await (const bytes of streamBounded(ref.locator.url, options)) {
        if (bytes.length > options.chunkBytes) throw new Error('Chunk budget exceeded');
        yield { bytes, contentType: 'text/plain; charset=utf-8', source: ref.locator.url };
      }
    } } : {}),
    async read(ref, _context, { maxBytes }) {
      if (ref.locator.type !== 'http') throw new Error('Unsupported locator');
      const bytes = await readBounded(ref.locator.url, maxBytes);
      if (bytes.byteLength > maxBytes) throw new Error('Document exceeds byte budget');
      return {
        bytes,
        contentType: 'text/plain; charset=utf-8',
        contentId: `k:${createHash('sha256').update(bytes).digest('hex').slice(0, 16)}`,
        source: ref.locator.url
      };
    }
  };
}
```

将对象放入 `OpenConfig.readers`；Core 对非本地引用选择首个 `canRead()` 匹配的 Reader。本例只处理 UTF-8 文本，若传输返回 HTML/二进制，应按你的知识来源合同拒绝或扩展 MIME 处理，而不是无条件当作指南。

`bytes` 是正文原始字节，V1 的 `contentId` 为 `k:` 加 SHA-256 十六进制值的前 16 位；Core 会重新计算核验。`source` 必须等于声明的 URL，不能随意换成缓存路径或重定向地址。`maxBytes` 单位为字节，不能用字符串长度替代。

成功时 `readDocuments()` 的成功槽位返回 `text`、`byteLength`、`contentId` 和原 `source`。伪造哈希/source 会得到 `CG_ADAPTER_CONTRACT_INVALID`，Reader 抛错投影为 `CG_READER_UNAVAILABLE`；批量读取中检查每项 `ok`。Reader 拥有网络资源，Core 不负责关掉它的连接池。


## 分页、代理与宿主快照

`stream` 的块预算与 `read` 的全文容量不同；完整来源可任意大，由模型决定读取范围及是否续读。每个块不超过 chunkBytes，UTF-8 可跨传输块，空正文也要输出带 MIME/source 的空块。Core 计算全文哈希，再返回所选范围；旧 Reader 只有 read 时采用有界全文回退，不能假定它能分页读取超出回退容量的来源。

源码 HTTP 参考的 agentForUrl 可接收宿主 ProxyAgent（Node 20/22/24），不向模型暴露代理认证。宿主负责关闭 Agent；Reader.close 关闭实际连接和自己创建的快照子目录。snapshot.directory 为仓库外的宿主专用绝对路径，maxBytes/maxEntries/ttlMs 控制缓存，不限制文档总大小。首次全文 GET 的强 ETag 与哈希建立绑定，续页的条件 HEAD 返回 304 后复用 Core 私有副本，避免重新读取和哈希整篇快照；不支持 HEAD、无验证器、弱 ETag 或超缓存预算时回退全文核验。200 更新由正文哈希拒绝旧 cursor，206/重定向/压缩响应被拒绝。普通 stream/read 仍核验完整磁盘快照。原始文本 URL 与渲染 HTML 是不同来源，HTML 提取需独立 Reader 和转换溯源。

外部索引即使不使用 access，也必须配置实际来源 Reader；Core 会核验每个最终文档和片段。利用 access.scan 可以复用当前查询的核验，减少重复读取。参考文本索引配置 maxCachedBytes/maxCachedEntries 控制保留成本，超额继续流式 Top-K，不截断正文；cachedBytes 是保守计账值，不是堆内存峰值。
