# 知识与 Adapter

先确认能力实际绑定了 Knowledge；最小 G0 没有知识，G2 才给 route.http 绑定 routing-guide，独立 G3 不自动拥有验证指南。可直接按[G2完整文件](../guides/progressive-discovery#g2-local-knowledge)核对 relative-file 路径和正文，再看逐项结果。Specification 是单独的 Provider 读取，不属于 selected 能力 Knowledge。

- `CG_KNOWLEDGE_NOT_ASSOCIATED`：已选能力没有匹配的 knowledgeId；核对选择和过滤。
- `CG_KNOWLEDGE_TYPE_UNSUPPORTED`：将 Collection ID 当成单篇文档读取。可先用 `listKnowledgeMembers()` 发现成员，再按成员 ID 精确读取。
- `CG_READER_UNCONFIGURED`：远程引用存在，但没有 Reader；配置 Reader，不要写成“没有知识”。
- `CG_READER_UNAVAILABLE`：匹配 Reader 执行失败；检查外部来源和资源清理。
- `CG_SOURCE_UNREADABLE`：本地或远程来源当前不可读。
- `CG_PATH_TRAVERSAL`：相对路径或真实路径逃离 Provider 根；修正定义和符号链接。

批量读取逐项返回错误。保留成功文档，不要把混合结果统一改成 `not found`。知识正文不在 Static Revision 中，每次读取使用新的 contentId。

全文接口默认最多 32 个原始 selected、每种过滤最多 128 个值、最多读取 8 篇文档，完整 JSON 响应最多 4194304 个 UTF-8 字节。原始数量在去重前检查；缺失身份及失败槽位也占响应空间。数量或整次响应超限时拆批或过滤；大正文使用 `readDocumentPage()` 或 `readSpecificationPage()`，默认每页 32768 字节，模型决定是否继续。文档总大小不是拒绝来源的理由。旧 Reader 未实现 stream 时，其全文回退仍受单次容量保护；实现流式协议即可读取任意大小来源。预算详见[结果元数据与预算](../reference/result-meta)。

## 文档太大怎么办

全文读取默认每篇最多返回 32768 字节，由 `read.maxBytes` 控制，超限产生逐项 `CG_BUDGET_EXCEEDED`，不会返回截断的正文。无需人工拆文件；改用 [正文分段读取](../reference/knowledge#正文分段读取)，传回 `nextCursor` 直到没有续页。分页默认 32768 字节，由独立的 `read.maxPageBytes` 控制；模型决定范围与是否继续。URL、本地目录和 node_modules 使用同一套分页规则，远程来源需配置流式 Reader。

如果是整次 JSON、文档数或过滤值超限，先拆批或缩小过滤。刚从旧版升级可查看 [1.0.1 升级清单](../getting-started/installation#从-101-升级到-110)，不要把全文预算与文档总大小混为一谈。

## Reader 返回值

Reader 的 contentId 必须为 `k:` 加原始 bytes 的 SHA-256 小写十六进制前 16 位；伪造 source、哈希或 MIME 返回 `CG_ADAPTER_CONTRACT_INVALID`。合法预算错误保留 `page_or_filter`，其他传输异常为 `CG_READER_UNAVAILABLE` 并移除私有详情。实现合同见[文档 Reader](../reference/reader)。
