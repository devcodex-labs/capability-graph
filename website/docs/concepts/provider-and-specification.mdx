# Provider 与能力

<span className="cg-status">可用</span>

Provider 是一组能力及其接入规则的所有者。每个 Provider 在有效启用范围内必须恰有一个权威来源，文件或数据库二选一。

Provider Specification 描述如何正确使用该 Provider，但正文不由 Core 管理。`provider.json` 只关联以下元数据：

- `specificationId` 和版本；
- 适用软件、版本范围和可选条件；
- Provider 自己提供的 `entryRef`。

接入方负责首次可发现入口、正文读取、适用版本判断、冲突处理和向 Agent 投递。Specification 不能覆盖用户指令、宿主 Policy、权限或执行授权。

## 为什么分开

静态图需要确定、可哈希的数据合同；规范正文可能独立发布、按版本变化或由宿主选择投递。分开后，Core 可以稳定校验身份和适用性，而不冒充规范分发系统。

## 能力建模

Static Capability 描述“Provider 能做什么以及何时应考虑它”，不是方法清单、运行实例或执行指令。一个可用节点至少要让第一轮发现回答：

- `name`：人类可读名称；
- `description`：能力解决什么问题；
- `whenToUse`：什么意图或条件下应考虑它；
- `distinction`：它与相邻能力的关键区别；
- 关系、知识和示例：按需补充，不把所有细节塞进目录。

粒度应稳定到可以独立选择，又不能细碎到每个函数或配置字段都是一个能力。静态图描述作者声明的领域结构，不从代码命名、目录或 Runtime 自动生成关系。

Core 校验 Schema、值、关系端点和环，不判断业务语义是否优秀。概念质量由 Provider 作者和评审流程负责，实践步骤见 [建模 Provider](../guides/model-a-provider#选择能力粒度)。
