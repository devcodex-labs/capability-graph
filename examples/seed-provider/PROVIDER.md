# Seed HTTP 接入约定

适用对象为本例的 `seed.http` 能力定义。Provider 负责将本文交给调用方；Capability Graph 只返回关联元数据，不读取、投递或强制执行本文。

- 静态能力描述类型和适用时机。实际路由属于指定项目与环境的 Runtime，不向 Catalog 写入每个 URL。
- 先从 Catalog 选择能力，再检查关系。`related` 表示参考关系，不自动把相邻能力加入已选集合。
- 修改已有接口时先确认项目、环境、方法、路径及构建身份。旧构建观察不证明当前源代码已注册同样的路由。
- 为 HTTP 路由增加输入校验时通常选择 `route.validation`；需要请求结构时显式补选 `schema.request`，再读取两者文档。
- 业务执行、权限、依赖安装、源码修改和测试由宿主负责。本例不定义这些操作的授权。

能力身份仅在概念语义连续时沿用。重命名显示名称不必换 ID；替换为不同概念时声明新 ID，并由接入方处理旧引用。删除能力不删除共享知识文件。
