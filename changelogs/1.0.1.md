# 1.0.1（待发布候选）

本版是有意的 Clean Break。公开 Registry、Tag 和网站发布须另行授权；在完成前不要将本地 `1.0.1` 包版本视为已发布。

## 新能力

- `requires` 声明必要上下文，`requiredBy` 从已验证正向边派生；`parents`、`specializes` 和 `requires` 分别校验无环。
- `resolveSelection()` 接受显式能力，返回完整依赖闭包、所有依赖边、直接原因及逐 Provider 修订来源。
- Document 必填 `role`，可选 `locale/title/summary/canonicalUrl`；Collection 与 Specification 文档可分页发现。
- `readDocuments()` 按 ID、用途和语言过滤，允许成员 ID 直选；`readSpecification()` 显式读取一组规范文档。
- `queryKnowledge()` 在检索前校验原始输入与最终目标数量/字节预算，并只给后端最小公开目标。

## 破坏性迁移

| 1.0.0 | 1.0.1 |
|---|---|
| `specification.entryRef` 单一引用 | 必填非空 `specification.documents`，每篇是 `role: "specification"` 的 Document |
| Document 无用途字段 | 每篇 Document 和 Collection 成员必填 `role` |
| 六类关系 | 八类关系，Adapter 必须支持 `requires/requiredBy` 完整有序页 |
| 静态哈希不含依赖与文档路由 | 元数据、关系、文档映射变化更新 Static Revision |
| 手工选择全部上下文能力 | Caller 显式选起点后可调用 `resolveSelection()` 获取必要闭包 |

`^1.0.0` 可能取得本版，因此旧 JSON、旧 Database Adapter 与 TypeScript 消费者应先迁移并在新包上重测。没有双 Schema 兼容层；旧 `entryRef`、缺 `role` 和源定义中的 `requiredBy` 会明确校验失败。能力执行、权限、Agent 意图判断、具体数据库/检索后端和统一 MCP Server 仍不属于 Core。
